DeepSeek MLA

MLA（Multi-head Latent Attention，多头潜在注意力） 是 DeepSeek-V2 首次提出、并在 DeepSeek-V3 中继续作为核心架构的注意力机制。它的根本动机是压缩推理阶段占用显存最大的 KV Cache，同时保持与标准多头注意力（MHA）相当的模型表达能力。

与 MHA 为每个头分别缓存完整的 Key 和 Value 不同，MLA 将所有头的内容 Key/Value 联合低秩压缩为共享潜向量 𝐜𝑡𝐾𝑉，并将单独投影的共享 RoPE Key 𝐤𝑡𝑅 一并存入 KV Cache；计算注意力时再从 𝐜𝑡𝐾𝑉 上投影恢复各头的内容 Key 和 Value。RoPE 位置部分与内容部分分开处理。

DeepSeek MoE

V3 拥有 671B 总参数，但每个 token 仅激活 37B，激活率约 5.5%。这种解耦使得模型能存储海量知识，同时将推理计算成本控制在一个中等规模密集模型的水平。

传统 MoE（如 GShard）面临两个核心痛点：知识混杂（少数大专家被迫学习差异极大的知识）与知识冗余（不同专家重复存储通用常识）。DeepSeekMoE 通过两项基础设计来应对：

1. 细粒度专家分割 在保持总参数不变的前提下，将专家的 FFN 隐藏维度切得更细，从而用更多数量的小专家来替代少数大专家。V3 的每个 MoE 层包含 256 个路由专家，每个专家的中间隐藏维度为 2048。这让专家能更灵活地组合，提升专业化程度。

2. 共享专家隔离 设置少量始终激活的共享专家，专门负责捕获跨上下文的通用知识；路由专家则得以更专注于各自的特异性模式，从而减少路由专家之间的知识冗余。

在 V3 的 61 层中，除前三层保留稠密 FFN 外，其余 58 层均采用上述 MoE 结构。

辅助损失自由的全局负载均衡

问题根源：在专家并行场景下，负载不均会导致“路由坍塌”——少数专家被过度使用，其余专家因梯度稀少而无法有效训练。传统方案是引入辅助损失来惩罚不均衡，但这相当于在语言建模的主目标之外“掺入干扰”，以牺牲模型性能为代价换取负载均衡。

V3 的解法：取消以全局负载均衡为目标的辅助损失，并为每个路由专家维护一个由负载动态调整的偏置项 𝑏𝑖。路由决策时，模型用 sigmoid 门控为每个 token 打分，再将偏置项加到分数上，选取分数最高的 Top-K 个专家。关键在于，偏置项仅用于路由选择，不参与最终的门控权重计算。专家负载偏高时调低其偏置，负载偏低时调高其偏置。

这样，负载均衡通过一个工程层面的动态调节机制来实现，主训练目标不再受到辅助损失的污染，从而在负载均衡与模型性能之间取得了更优的平衡。作为补充，V3 仍保留了一个极小的序列级辅助损失，仅用于防止单个序列内部出现极端失衡，而非全局负载调控。

Persistent Kernel
  1. 减少Kernel反复启动开销。
  2. 减轻wave quantization现象。波量化是指当总工作量（如输出 tile 数）不能被 GPU 的 SM 数量整除时，会导致最后一“波”计算中只有部分 SM 在工作，其余闲置，造成利用率的骤降。在任务数量动态变化的 MoE 中，这个问题会被进一步放大。Persistent Kernel 让固定的 CTA 集合动态地从全局队列中“领取”下一个可用 tile，而不是静态地预先分配任务。这意味着先完成的 CTA 可以立即接手新任务，从而自然地在各个 SM 之间实现了动态负载均衡，有效“填平”了波量化造成的利用率低谷。
  3. 跨 Tile 的流水线化。传统模式下，CTA 在完成一个 tile 后便会退出，下一个 tile 需要重新经历完整的“启动-加载数据-计算-写回”流程，这被称为“序言”（prologue）和“尾声”（epilogue）开销。 Persistent CTA 因为持续存活，可以在处理完当前 tile 后，立即开始加载下一个 tile 所需的数据，从而将不同 tile 的“尾声”与“序言”重叠起来。这种跨 tile 的流水线化隐藏了数据搬运和初始化延迟，使得计算单元能够更持续地保持忙碌。
  4. 提升缓存复用与数据局部性。在 MoE 的 Grouped GEMM 中，不同专家可能共享相同的激活或权重分片。Persistent CTA 在处理连续或相关的 tile 时，有机会在片上缓存（如 L2 cache）中复用数据。

  • 共享权重包括：

    • 共享专家。始终被激活的专家。
    • 专家绑定。跨层复用专家参数。
  1. Persistent Kernel 的“常驻”特性使其成为构建 Mega-kernel。

代价：实现复杂度更高（需要手动管理任务队列和同步），并且可能因常驻而带来更高的寄存器压力或与并发内核的资源争用问题。

GLM 5.2/5.3 IndexShare

https://arxiv.org/abs/2603.12201

在 DSA（DeepSeek Sparse Attention）机制中，每一层都有一个轻量的“索引器 (Indexer)”，它负责从长达百万 token 的历史中，为本层的每个 token 快速筛选出最相关的 Top-k 个 token，后续的注意力计算只在这些被选中的 token 上进行，以此实现稀疏化。

注意到相邻层索引器选出的 Top-k token 集合高度重叠（重叠度高达 70% 到 100%）。这意味着下一层的索引器常常在“重新发现”上一层刚刚选过的位置，造成了大量的重复计算。

IndexShare 利用这种重叠性，让一组连续层共享同一次索引选择的结果。具体采用 “1 层 Full + 3 层 Shared” 的四层分组模式： - Full 层（组长）：在每 4 层中，有 1 层会实际运行索引器，完成一次完整的 Top-k token 选择。 - Shared 层（组员）：紧随其后的 3 层则完全不拥有自己的索引器（不建参数、不做投影、不跑索引选择），直接复用其组长（Full 层）选出的那组 Top-k token 位置来进行自己的稀疏注意力计算。

索引计算量被压缩到原来的 1/4。
