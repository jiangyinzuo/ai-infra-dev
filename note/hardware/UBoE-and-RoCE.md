参考资料：《昇腾950 NPU架构白皮书》

* **RoCE** 是行业标准技术（由 IBTA 组织制定），主要用于将 **InfiniBand 协议** 封装在以太网中。
* **UBoE（UB over Ethernet）** 是华为昇腾体系的类似思路——它把华为自研的 **UB（Unified Bus）高性能总线协议** 封装在以太网中。
    - 根据IETF的UBoE草案，其实际封装是将原生UB上层协议数据封装在IPv4/IPv6和UDP报文之中，再承载于以太网上（based on IPv4/IPv6 and UDP over Ethernet）。
    - UBoE并非像RoCEv1那样直接把IB/UB报文塞进以太网帧，而是采用了与RoCEv2类似的UDP/IP封装路径。

它们的底层逻辑是一致的：利用以太网无处不在的成熟生态和高带宽（400G/800G），来承载私有或高性能的底层集群通信协议。

## UBoE
### 一、 为什么要做 UB 接入以太网络（UBoE）？

1. **打破封闭生态，降低建网成本**：
纯私有的高性能互联网络通常需要专用、封闭的交换机和线缆，造价极其昂贵且供应商锁定。通过 UBoE，可以将高性能的 UB 协议跑在标准、成熟、规模化量产的**以太网基础设施**（如 400G/800G 标准以太网交换机）之上，大幅降低智算中心的建设成本。
2. **满足大规模、跨节点水平扩展（Scale-out）的需求**：
芯片级总线（如 NVLink）的物理距离和扩展节点数有限。当 AI 大模型集群扩展到万卡甚至十万卡规模时，必须依赖具备强大路由、多路径负载均衡（ECMP）能力的高性能以太网织构（Lossless Ethernet / 丢包无损以太网）来实现超大规模水平扩展。
3. **异构网络与存储的融合**：
智算集群不仅需要 NPU 之间进行极速梯度同步，还需要与标准 CPU 服务器、分布式存储（如 NVMe-oF、Ceph）进行数据交互。支持以太网接入意味着 NPU 集群可以无缝融入现有的企业级数据中心网络。

### 二、 哪些设备是基于以太网的？

以太网是当今全球应用最广泛的网络技术，几乎现代 IT 基础设施中的绝大多数网络和计算设备都基于以太网：

1. **数据中心交换机与路由器**：现代数据中心的 Spine-Leaf（脊叶）架构交换机、企业级核心/汇聚/接入交换机。
2. **服务器与网卡（NIC / SmartNIC / DPU）**：通用 x86/ARM 服务器、搭载标准以太网网卡的计算节点。
3. **存储设备**：支持 IP-SAN、NAS、分布式对象存储和块存储的存储阵列。
4. **终端设备**：企业办公电脑、工控机、IoT 物联网设备等（虽然在 AI 集群中，我们讨论的主要是面向数据中心的高速 400G/800G 以太网设备）。

### 三、 以太网属于 OSI 模型的哪一层？又是什么？

#### 1. 什么是以太网？

以太网（Ethernet）是由 IEEE 802.3 标准定义的一系列**局域网（LAN）通信技术**。它规定了网络中电缆、光纤的物理连接方式、信号传输的电气特性、帧（Frame）的结构格式以及节点之间如何安全地共享通信介质。

#### 2. 以太网在 OSI 模型中的归属

以太网主要横跨 **OSI 七层模型** 的底两层：

* **物理层（Layer 1）**：
* **职责**：负责在物理介质（如铜缆、单模/多模光纤）上传输原始的二进制比特流。
* **对应体现**：白皮书中提到的 `1x400/200/100/50/25Gbps` 或 `2x200/100/50/25Gbps` 的 **Port Bifurcation（端口分叉）** 和物理速率，就属于物理层和电气/光学接口的范畴。


* **数据链路层（Layer 2）**：
* **职责**：负责将物理层的比特流组合成**以太网数据帧（Ethernet Frame）**，提供 MAC 地址寻址、物理链路的流量控制、差错校验（FCS帧校验序列）以及介质访问控制。


> 白皮书中的 **UBoE** 实际上是在以太网的 **Layer 2（数据链路层）** 或配合 **Layer 3/4（IP/RoCEv2 协议栈）** 的基础上，将昇腾的 UB 传输层协议进行封装，使其能够像 RoCE 一样在标准无损以太网交换机中转发，从而兼顾了专有总线的高性能与以太网的高兼容性。

> 除了以太网，IP协议也可以跑在WiFi、4G、5G甚至信鸽（RFC 1149）上。


## RoCE

**RoCE** 的全称就是 **RDMA over Converged Ethernet**（基于融合以太网的远程直接内存访问），核心目的，是把原本需要在专有硬件和网络（如 InfiniBand）上才能运行的 **RDMA（远程直接内存访问）** 技术，搬到标准的以太网架构上来运行。

### 一、 什么是 RDMA？为什么要在以太网上跑？

* **传统网络传输**：CPU 发送数据时，需要先将数据从应用内存复制到内核缓冲区，经过 TCP/IP 协议栈逐层打包，再通过网卡发送。接收端也要经历相反的繁琐过程，这会消耗大量的 CPU 算力和带来较高的延迟。
* **RDMA（Remote Direct Memory Access）**：允许一台计算机的网卡**直接读取或写入另一台计算机的内存**，绕过了操作系统内核和 CPU 的参与，实现了“零拷贝”和“超低时延”。
* **为什么要用以太网？** 早期 RDMA 必须依赖 InfiniBand（IB）网络，但 IB 网卡和交换机价格极其昂贵、生态封闭。RoCE 的出现，就是让用户可以用普通（但性能强化过）的**以太网交换机和网卡**，享受到接近 InfiniBand 的极致性能。

### 二、 RoCE 的两个版本（v1 与 v2）

RoCE 在发展过程中演进出了两个主要版本，这决定了它在网络模型中的位置：

1. **RoCE v1（基于以太网链路层）**：
* 它直接封装在以太网二层数据帧中（Ethertype 0x8915）。
* **局限性**：因为它没有 IP 层，所以**不能跨网段（路由器）传输**，只能在同一个二层局域网（VLAN / 广播域）内使用。

2. **RoCE v2（基于 UDP/IP 协议栈，最常用）**：
* 这是现代智算中心（如大模型训练集群）的主流选择。它将 RDMA 报文封装在 **UDP 报文**中（通常使用固定的端口号 4791），外面再套上 IP 头。
* **优势**：因为有了 IP 地址，RoCE v2 **可以跨三层网络进行路由转发**，能够在大规模数据中心复杂的 Spine-Leaf 拓扑中自由穿梭。

### 三、 为什么叫“融合以太网”（Converged Ethernet）？

普通以太网有一个致命弱点：**会丢包**。当网络拥堵时，交换机会直接丢弃多余的数据包，依靠上层的 TCP 来重传。但 RDMA（尤其是 RoCE）对丢包极其敏感，一旦丢包会导致严重的性能崩塌（性能暴跌甚至死锁）。

因此，跑 RoCE 的以太网必须是“无损以太网”（Lossless Ethernet），需要借助以下关键技术将普通以太网“改造”成融合以太网：

* **PFC（Priority-based Flow Control，基于优先级的流量控制）**：当交换机缓冲区快满时，通过暂停信号让上游设备暂停发送，避免丢包。
* **ECN（Explicit Congestion Notification，显式拥塞通知）**：在网络出现拥堵苗头时，在数据包上打上标记，让端侧主动减速。
