## PCIe协议栈

*   **事务层 (Transaction Layer)**：这是PCIe的最高协议层。它负责组装和解析**事务层数据包（TLP）**，并管理基于信用的流控制。虽然有时会被类比为OSI的**传输层**，但它的职责边界清晰，并不提供跨网络的端到端连接管理。
*   **数据链路层 (Data Link Layer)**：位于中间，负责链路上的可靠性。它通过**数据链路层数据包（DLLP）**进行错误检测（如使用LCRC）和链路管理，功能上对应OSI的**数据链路层**。
*   **物理层 (Physical Layer)**：最底层，负责在物理链路上串行地发送和接收比特流，对应OSI的**物理层**。

### 为什么PCIe可以“跳过”网络层？

这源于PCIe的设计初衷和它所处的“世界”。PCIe被设计为一个**本地、单主机域内的互连总线**，而非一个可以任意扩展的网络。

*   **简单的树状拓扑**：PCIe的典型拓扑是一个以**根复合体（Root Complex）**为顶点的树状结构。数据包的路由依赖于这种固定的层级和基于地址的路由方式，而不是像IP网络那样，需要网络层在复杂的网状拓扑中动态选择最佳路径。
*   **“没有路由信息”的论断**：有技术讨论直指核心，认为PCIe“**根本没有（网络层所需的）路由信息**”。这是因为它不需要在多个可能的路径之间进行选择，其寻址和转发机制在事务层和数据链路层就已经定义完毕。
*   **网络层被视为“冗余”**：一份技术文档指出，在PCIe所适用的有限设备互连场景中，**网络层可以被视为是冗余的**，并且额外增加网络层反而会引入**可观的延迟**。PCIe的设计哲学就是在它预定的应用范围内，用最精简的层次实现最低的延迟和最高的效率。

### 与灵衢总线的对比：场景决定架构


| 特性 | **PCIe** | **灵衢总线 (UnifiedBus)** |
| :--- | :--- | :--- |
| **设计场景** | 单主机内的**本地设备互连**（CPU与外设） | **k级别大规模**超节点互连（机架级/集群级） |
| **拓扑规模** | 树状，规模有限 | 网状，规模可达数千节点 |
| **链路介质** | 主要为板级/连接器**电链路** | 包含**光互连**（LPO/NPO/CPO等） |
| **网络层** | **无**（路由功能内嵌于低层，无需独立网络层） | **有**（负责多路径路由、拥塞标记、死锁避免） |
| **传输层** | **无**（功能由事务层/链路层分担） | **有**（负责端到端重传、拥塞控制） |
| **可靠性假设** | 默认链路相对可靠，由**链路层重传（LLR）** 保障 | 默认**大规模光互连不可靠**，需**逐层协同**保障 |

PCIe“本地、封闭、电互连”，通过精简掉网络层和传输层，换取了极致的低延迟和低开销。
灵衢总线面向的是“大规模、开放、光互连”的挑战，因此必须重新引入并强化网络层与传输层，以构建端到端的可靠性。

网络协议栈有网络层传输层，但PCIe总线协议栈没有的原因：
- 以太网散播在全球，被认为是不可靠的，需要一些超时重传流控机制。
- 但总线被认为是可靠的。是一块主板上的通信。

Huawei在19年后不能参加PCIe标准了，所以做了UB。

## 灵衢总线协议栈

超节点互联协议：跨节点，也不稳定，所以也有网络层+传输层。

SSU -> 其实就是SSD的控制器。

灵衢总线的特点：
- 物理层：能可变速率机制、故障检测自动降lane降速。不过通用的网络协议没有这种功能。（私有的网络有）
- 数据链路层：Flit高效传输数据、多link方式提供更大组合带宽（PPT前两项）
- 网络层：精简地址，降低转发时延，不过也可以兼容IPv4/v6
- 传输层
    - RTP CTP UTP TP Bypass。RTP对标网络协议TCP，UTP对标网络协议的IP。
- 事务层
    - 四种事务：内存事务，消息事务，维护事务，
    - 管理事务
        - 器件配置
    - 四种事务服务模式
        - 可靠/不可靠R/U
        - 事务序：O/NO
    - atomic原子操作

点对点：数据链路层传输。
端到端：传输层传输。总线协议通常没有传输层，因为没有端到端通信。

- 功能层（在事务层基础上实现）
    - CPU load/store同步访问；异步访问
        - 小数据适合同步；大数据适合异步
    - UMMU内存管理，统一内存池化
        - 页表
        - 共享虚拟内存
        - UB并不认为自己是网络，它认为自己是个计算机，管理各种资源
            - UB FM（Fabric Manager）
