PD 分离 + P 端 DCP

PD 分离让 P 处理输入 prompt，让 D 在接收 KV 后逐 token 生成。两个实例独立调度，并分别配置并行度。

MLA + NIXL Pull。P、D 两端共用图中的 TP，两端 PCP=1。

NIXL Pull 在 PCP=1 时要求 P 端 DCP 为 1 或等于 TP。

P 端可通过 --cp-kv-cache-interleave-size 指定每次连续分配给一个 TP rank 的 token 数。显式设置时，该值须整除实际 KV block size。省略时，vLLM 为 NIXL Pull 自动按缓存布局选择。图中两端的 KV block size 均取该值，演示按整块交接。

对容量和延迟的影响

  • P 端开启 DCP 后，分片降低每张卡的 KV 占用。同样的显存预算可容纳更多长 prompt 或缓存的前缀，缓解 KV 容量不足造成的排队。
  • D 端每步 attention 读取本地完整 KV，省去 DCP 的跨 TP rank 结果合并。D 的显存需要容纳并发请求的完整上下文。
  • 端到端首 token 延迟还取决于 prefill 计算、P 端组内通信和 P 到 D 的 KV 交接耗时。
